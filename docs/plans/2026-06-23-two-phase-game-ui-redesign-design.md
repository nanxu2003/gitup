# 两阶段国风游戏 UI 改造设计

## 目标

使用 `assets/images/` 中已经生成的 4 张场景背景、6 张角色立绘和 1 张物品图集，参考现有四张截图的构图与氛围重做 Flutter 界面。第一阶段完成世界地图、战斗、招募和登录奖励；第二阶段把同一套视觉系统扩展到其余游戏页面。运行时不再使用四张 `_reference.png`，最终删除这些文件。界面不出现充值、付费或购买入口。

## 选定方案

采用模块化分层复刻。每个重点页面由场景背景、代码 UI、角色立绘和光效遮罩组成。标题、按钮、血条、关卡节点、奖励卡和动态数值继续由 Flutter 渲染，图片只承载环境、人物和物品美术。

整页合成图虽然接近截图，但会牺牲动态数据与响应式；纯代码换皮则无法解决当前页面单调的问题，因此不采用。

## 素材映射

- 世界地图：浮空山河背景 + 白紫羽翼引导角色。
- 战斗：燃烧城镇校场背景 + 红黑长戟武将与银甲狼将。
- 招募：红黑宫殿背景 + 持扇女将与紫甲武将。
- 登录奖励：赤焰山城背景 + 银甲赤发吕布。
- 登录奖励与招募结果：八种物品图集。

生成素材先改为语义化路径。绿幕或品红底角色、物品图会转换成透明 PNG，页面不直接执行实时抠色。

## 第一阶段：四个重点页面

### 世界地图

保留章节切换、星级、解锁与关卡弹层。纵向地图使用相对坐标放置城池节点，叠加告警、锁定和完成状态；引导角色从左下压边进入画面。底部详情保持可读并避开角色。

### 战斗

保留 `BattleEngine`、目标选择、技能、自动战斗、倍速和结算逻辑。背景中央留给双方阵列，顶部显示战局标题和回合，底部角色立绘压边；血条、伤害数字与技能光效全部由 Flutter 绘制。

### 招募

保留 `RecruitService` 和现有铜钱、招募令资源逻辑，不提供充值或购买入口。宫殿背景上叠加主视觉角色、四张候选武将卡、保底信息、单次与十连按钮。卡牌文案和概率均为动态 UI。

### 登录奖励

保留本地三日奖励状态与自动存档。吕布立绘位于中央上部，底部展示三日奖励卡与物品图标。文案只描述免费登录领取，不出现充值、首充或付费诱导。

## 第二阶段：全部页面

新增统一的背景脚手架，为主页、城池、内政、武将、阵容、背包、任务、剧情事件、详情、设置、帮助和协议等页面提供图片背景、暗色可读遮罩、金属边框和安全区布局。页面按场景复用四张背景，不为了数量重复生成图片：

- 城池、内政、招募、武将与背包使用宫殿类背景。
- 世界、任务、剧情与关卡使用山河或赤焰背景。
- 战斗、阵容与战斗结果使用校场背景。
- 设置、帮助、反馈与协议使用低对比宫殿背景和更强阅读遮罩。

业务模型、路由、存档和数值系统保持不变，只替换表现层。

## 响应式、失败降级与可访问性

页面使用 `LayoutBuilder`、相对定位和 `BoxFit.cover` 适配常见手机比例。所有点击目标至少保持可操作尺寸，底部操作区避开安全区。图片加载失败时显示同色渐变；文字与交互仍可使用。阅读型页面使用高不透明度面板，避免背景降低对比度。

## 验证

- 测试生产代码和资产清单中不存在 `_reference.png` 引用。
- Widget 测试覆盖四个重点页面的背景层、角色层、关键标题和交互。
- 登录奖励和招募文案中不存在充值、首充、付费、购买等入口表达。
- 全部页面使用统一背景脚手架或显式图片背景。
- 运行 `dart format`、`flutter analyze` 与 `flutter test`。
- 在可用模拟器上逐页检查溢出、遮挡、图片解码和关键按钮。
