# 截图风格游戏页面改造设计

## 目标

将四张参考截图中的三国角色、场景、边框与墨迹装饰用于现有 Flutter 游戏，使世界地图、战斗、招募和登录奖励页面在构图、层次与氛围上贴近参考图，同时保留现有存档、关卡、战斗和招募逻辑。

## 页面映射

- 图 1 → `WorldMapScreen`：纵向山河地图、关卡建筑节点、告警标记、左下角色压边装饰。
- 图 2 → `BattleScreen`：燃烧战场、双方阵列、血条和伤害数字、底部武将压边装饰。
- 图 3 → 新增 `LoginRewardOverlay`：吕布主题登录豪礼、三日奖励卡、可领取状态。
- 图 4 → `RecruitScreen`：暗色主城遮罩、红金招募展板、四张武将候选卡、底部角色压边装饰。

## 视觉架构

素材从用户提供的截图中复用。页面使用 `Stack` 分三层：全屏场景素材、Flutter 数据与交互层、角色/标题/墨迹前景层。统一使用暗棕木框、旧金描边、朱红告警、青蓝能量与高对比白色书法标题，适配安全区和不同纵横比。

为避免整张截图仅作为不可交互贴图，关卡节点、战斗控制、招募选择和奖励领取均由 Flutter Widget 实现；参考截图负责提供角色与氛围，当前游戏模型负责提供动态文字、数值和状态。

## 行为与数据

- 世界地图读取现有章节和关卡解锁状态，点击节点继续进入剧情或战斗。
- 战斗页继续使用 `BattleEngine`，只替换表现层；伤害、回合和胜负逻辑不变。
- 招募页继续调用 `RecruitService` 并扣除现有资源；结果使用新的卡牌展板显示。
- 登录豪礼首次进入主页时弹出；奖励领取写回当前 `GameSave` 并自动保存。首版提供三日奖励视觉和当日可领取按钮，不引入联网签到。

## 响应式与降级

以 `LayoutBuilder` 和相对定位适配手机尺寸。背景使用 `BoxFit.cover`，关键按钮保留在安全区内；资源加载失败时显示同色渐变和 Flutter 图标，不阻断游戏功能。

## 验证

- `flutter analyze` 无新增问题。
- Widget 测试验证四个页面的关键标题、交互入口和奖励弹窗。
- iOS 模拟器运行后截取页面，与四张参考图逐页比对构图、层次、可读性与点击区域。
